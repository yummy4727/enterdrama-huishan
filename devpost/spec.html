回山试玩版 — Technical Spec

蓝图一句话：一堆静态文件——原生 HTML/CSS/JS 播放器 + 构建期 Node 脚本裁《回山》正本资产，无框架、无后端、无运行时依赖，任何静态托管都能跑。

这套系统怎么运转（大白话）

读完这段你应该能向别人复述这个 app 是怎么回事（对应 spec.md > How This Works）

整个产品分两段工作，复杂度全部前置在构建期，玩家手机上只有最薄的一层：

  1. 构建期（你的电脑，跑一次）：Node 脚本读《回山》正本 script.json（1190 步），裁出 seq 1–368 存成 script-slice.json（文字零改动）；把切片用到的配音、BGM、背景图、头像拷进项目，图片压成 WebP（原图一张 3MB，手机太重）；盘点每步的配音文件，缺的生成一张清单，拿去走进戏的 TTS 管线补生成。
  2. 运行期（玩家手机）：浏览器打开页面，轻触一下解锁声音，播放器按 seq 顺序读剧本数据——每步是一句台词/一次背景切换/一次音乐切换。台词配音出声、文字打字机逐字出现，点屏幕跳下一句。走到 66、272 两步弹选择，选完跳分支、汇合继续。走到 368 画面定格，结算页弹出：悬念文案、你的选择摘要、"去入戏 App 看结局"。
  3. 进度：每播一步往 localStorage（浏览器给每个网站的一块本地小存储）记一笔，关页再开直接从断点接着播。

数据模型

三份数据各住哪、怎么更新、离开再回来发生什么（对应 spec.md > Data Model）

① script-slice.json（构建产物，浏览器只读）：seq 1–368 步数组，字段沿用正本（type / text / char_id / background / music / audio / branches / default_goto_seq）。

② audio-manifest.json（构建产物）：seq → mp3 映射；缺失的 seq 不在映射里，播放器静默跳过。

③ localStorage（玩家浏览器里，每步更新）：

{ "seq": 89, "choices": { "66": 2 } }

开页读它恢复断点；"重玩一次"删它。key 挂 v1 后缀，改结构时换版本不冲突。

外部依赖与兜底

运行时零外部服务；构建期只有 Node + sharp

项说明
运行时服务无。不调 API，无 key、无限额、无费用。
构建期Node ≥ 18；sharp（仅 devDependency，压缩图片）；sharp 不可用时降级直接拷原图、构建不失败。
TTS 补生成入戏现成管线（本机资产）；构建期产出 audio-missing.json 投喂，mp3 放回后重跑构建即纳入 manifest。
托管本地 npx serve .（试玩/录屏）；腾讯云 nginx（enterdrama.cn 子路径，可选，6-ship 定细节）。

重要失败模式（各配一条兜底）

  • 台词音频缺失/加载慢 → 静默降级：台词照常打字机推进，绝不阻塞白屏。
  • 背景图加载失败 → 暗色底 + 场景名淡字占位，流程不中断。
  • localStorage 不可用 → 无进度照常玩，退出即失，不报错。
  • 微信自动播放策略差异 → 轻触统一解锁 + 首句失败静默重试一次；真机实测校准。

决策记录

朱砂=学习者拍板，蓝=派生实现细节，金=构建期核对项

拍板原生 HTML/CSS/JS + Node 构建脚本——接受推荐，放弃 Vite+TS 的类型/热更新换零依赖与微信兼容确定性。

拍板部署腾讯云（enterdrama.cn 子路径）作 Devpost 可选 Try-it-out 链接；GitHub 公开仓库 URL 是必交物、不可用其他地址替代（已核实 skill pack 规则）。

拍板资产不入仓——防后续 TTS 重生成/更新膨胀（实测全量约 90MB，其实在限制内，但仓库历史干净是净收益）。

拍板台词 TTS 走入戏现有管线——音色与正式版一致，导流一致性最好；旁白全量现成，只补台词行。

派生图片压 WebP、字体子集化、localStorage schema、构建脚本产出物——由以上决定导出。

核对旁白 nar 奇数序号 ↔ seq 映射规则——构建期盘点脚本逐条对齐正本 audio 引用与 narration/ 实际文件，manifest + 缺口报告即验证证据。

核对台词行配音全量缺失（学习者确认）→ TTS 管线补生成 368 步内台词；验收 = manifest 无缺口。

核对微信自动播放/解锁行为差异——真机实测校准轻触解锁方案（PRD Open Questions 顺延）。
