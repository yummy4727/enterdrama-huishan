推荐导览路线（六站）

  1. scripts/build.mjs — 一切复杂度前置的地方。看三点：顶部 SLICE_END = 368 决定正本裁多少；STAGE 暂存目录 + 末尾重试换入（构建中途页面请求不再撞 404，头像裂图的根因修复）；audio-missing.json 缺口清单怎么喂 TTS 管线。
  2. data/script-slice.json + audio-manifest.json — 播放器唯一的数据源。每一步就是「一句台词 / 一次背景 / 一次音乐 / 一个分岔」；manifest 里缺的 seq 不出现，运行时静默跳过——「绝不阻塞」承诺的数据侧保障。
  3. js/main.js — 启动与全局交互。看三点：beginFrom() 里 BGM 与首句配音的首次 play() 都在同一次点击手势内完成（微信解锁音频的关键）；?seq= 调试跳转（仅验收用，会覆盖存档）；全局 click 与 tapGate/choices 的冒泡隔离。
  4. js/player.js — 步进状态机，运行时最核心的 200 行。看四点：jump() 跳句先停上一句配音（防混声）；advance() 打字未完先补全；branch 步无 choices 即 AUTO 分支按正本汇合点自动跳；finishTyping() 里 current.end 触发 1400ms 后的结算页。
  5. js/choices.js + js/endscreen.js — 内核的两端：入口分岔与出口导流。选项文案照抄正本不缩写；「（不答话）」走 default_goto_seq；结算页摘要从 localStorage 的 choices 反查选项原文，沉默支显示「他没答话。」。
  6. js/storage.js + js/ads.js — 两个薄层。storage 每步渲染前写 seq，隐私模式静默降级；ads 是纯占位结构（banner + 3 秒倒计时假卡），不接真实广告网络——POC 边界在这里。

值得带走复用的实践

实践本项目里的落点
复用手势内同步解锁音频轻触首屏的点击回调里同步起 BGM 与首句配音（main.js > beginFrom），一次手势完成 AudioContext 解锁——微信内置浏览器自动播放策略的稳妥解法。
复用构建期暂存 + 原子换入资产先写 data/.assets-staging，全部就绪后 rename 换入正式目录（build.mjs 末尾带 EBUSY 重试）。任何「边更新边服务」的静态站都适用，杜绝换装 404 空窗。
复用缺口清单驱动补齐构建期盘点出 audio-missing.json（含台词原文，可直接投喂 TTS），补完重跑构建即清零——资源补齐类任务先出清单再批量跑，不阻塞主线。
复用运行时静默降级配音缺失/加载慢 → 静默跳过；头像加载失败 → 退避重试后收起头像圈；localStorage 不可用 → 无进度照常玩。关键路径上没有一处会白屏或卡死。
复用?参数调试跳转?seq=N 跳过轻触直达任意步，验收分支/结算不用从头点——线性播放器类产品的通用调试模式。

导览完若要动手改：js/ 六个文件即全部运行时；data/ 一律不手改，坏了重跑 node scripts/build.mjs。
